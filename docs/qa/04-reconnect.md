# QA 角色 4：中途斷線重連的玩家

**目標：** 斷線期間發生淘汰，回來後畫面要補上；並量測網路掉了之後要多久才恢復（PR-14 曾看到超過 30 秒）。
**腳本：** `role4-reconnect.mjs`、`role4b-silent-drop.mjs`、`role4c-server-restart.mjs`

## A. 瀏覽器離線（CDP `setOffline`）

每次都是 5 位玩家的真實遊戲，其中「甲」斷線。時間從 `setOffline(false)` 算起。

| 試驗 | 斷線時間 | 斷線期間淘汰甲 | 恢復時間 | 恢復後畫面                       | Game ID                                |
| ---- | -------- | -------------- | -------- | -------------------------------- | -------------------------------------- |
| t1   | 3 秒     | 否             | 1.5 秒   | 查看題目卡，存活                 | `4c7c5809-e9cb-4fc2-b0ee-e25f628a93ef` |
| t2   | 10 秒    | 是             | 8.0 秒   | 「你被淘汰了」，已淘汰，題目隱藏 | `84b4297d-f0ad-4916-b0bb-291033aefec1` |
| t3   | 35 秒    | 是             | 3.7 秒   | 「你被淘汰了」，已淘汰，題目隱藏 | `e446d1c4-34d6-4750-a1a9-1093d27040a2` |
| t4   | 3 秒     | 否             | 1.4 秒   | 同 t1                            | `98de3863-faf3-4fa5-b374-488a86eea793` |
| t5   | 3 秒     | 否             | 3.9 秒   | 同 t1                            | `366cb753-6a87-43c7-bbfc-c3f06aa9a1b5` |

- 手機在斷線後馬上顯示「連線中…」，卡片不再畫出來，所以回來時題目一定是隱藏的。
- Server 的 Log 有 `PLAYER_DISCONNECTED`（斷線後約 3 秒的 debounce 才寫）與 `PLAYER_RECONNECTED`。
- 淘汰發生在斷線期間時，回來後手機直接是「已淘汰」，主持人頁也沒有錯亂。

**恢復時間不固定（1.4 到 8.0 秒）的原因（量到的）：** Chromium 在離線模擬時會立刻關掉 WebSocket，Client 開始用 Socket.IO 的退避重連（`reconnectionDelay` 500 毫秒、每次加倍、上限 10 秒、±50% 亂數，見 `src/client/net/socket.ts`）。腳本在 t2 記到頁面出現「Failed to load resource」（我推論是失敗的重連嘗試）的時間點是 +0.7、1.6、4.0、7.9 秒，下一次落在 +17.9 秒，網路在 +10 秒就回來了，所以等了 8 秒。t3 的嘗試落在 +8.6、18.6、28.6，下一次 +38.7 秒，網路在 +35 秒回來，等 3.7 秒。每兩次嘗試的間隔從 0.5 秒起每次加倍，到 10 秒封頂（兩個試驗裡後面幾次的間隔都剛好是 10.0 秒，與 socket.io-client 在加上亂數之後才套用上限的寫法一致）。也就是說，**恢復時間 = 網路回來後，等到下一次退避計時結束**，只靠退避，最長約 10 秒。若看到更久，要另外找原因，例如 B 小節的心跳逾時，或新連線的 TCP 一直沒回應（Socket.IO 連線逾時 20 秒）。

## B. 網路無聲中斷（模擬切換 Wi-Fi 到行動網路）

A 的做法不能代表真機，因為真機換網路時，舊的 TCP 連線不會被關閉，只是沒有封包。`role4b-silent-drop.mjs` 在手機與 Server 之間放一個 TCP 代理：舊連線停止轉送（不送 FIN 也不送 RST），新連線正常。主持人在網路中斷後 0.6 秒淘汰這位玩家。

| 項目                       | 結果                                                                             |
| -------------------------- | -------------------------------------------------------------------------------- |
| 手機畫面出現「連線中…」    | **44.9 秒**                                                                      |
| 手機畫面變成「你被淘汰了」 | **45.4 秒**（0.5 秒後新連線建立並補上狀態）                                      |
| 這 45 秒內手機畫面         | 維持舊狀態（存活、可查看題目），完全沒提示                                       |
| 主持人看到這位玩家離線     | 沒有（Log 沒有 `PLAYER_DISCONNECTED`，因為 Server 端舊 socket 也要等 ping 逾時） |
| Game ID                    | `c4d4fe10-f3b5-4763-a6c8-3e7294e3e299`                                           |

**原因（程式碼與量測都對得上）：** Server 沒有設定 Engine.IO 的 `pingInterval`、`pingTimeout`，用預設值 25 秒與 20 秒（`node_modules/engine.io/build/server.js`）。Client 要等「25 + 20 = 45 秒」沒收到 ping 才認定連線已死。在這之前它不知道網路壞了，所以不會重連。45.4 秒的量測與這個值吻合。

**PR-14 看到的「超過 30 秒」：** 與 B 同一個機制。PR-14 的測試用 `setOffline(true)` 再 `setOffline(false)`，若當時舊 WebSocket 沒有立刻被關掉，Client 就要等 45 秒的 ping 逾時才會重連。這一點是推論，我沒有重現 PR-14 的那一次。另外一個可能的疊加（沒有量測，只是從程式碼推）：重連時若新連線的 TCP 一直沒有回應，Socket.IO 的連線逾時預設 20 秒，再加退避，最壞會超過 30 秒。

**影響：** 手機網路切換後最久 45 秒看不到最新狀態。題目卡不會洩漏秘密（舊畫面本來就只顯示自己的資料），但玩家可能看著過時的「存活」。判為 P2，見 [QA-01](bugs.md#qa-01)。修復 PR 把 `pingInterval`、`pingTimeout` 都改成 10 秒（最久 20 秒），代價是多一點流量；不用 5 秒的逾時，因為手機短暫卡頓時容易誤判斷線。結果見下一節。

### 修復後

同一支腳本 `role4b-silent-drop.mjs`，同一個流程（5 人遊戲，無聲中斷後 0.6 秒主持人淘汰這位玩家），量測兩次：

| 項目                    | 修復前  | 修復後（兩次） | 修復後，中斷 2 秒後觸發 `online` 事件 |
| ----------------------- | ------- | -------------- | ------------------------------------- |
| 手機畫面出現「連線中…」 | 45.0 秒 | 19.9、19.9 秒  | 2.6 秒                                |
| 手機畫面補上淘汰或結果  | 45.5 秒 | 20.4、20.4 秒  | 6.0 秒（事件後約 4 秒）               |

第三欄模擬手機換網路後瀏覽器送出 `online` 事件：Client 直接換新連線，用原本的 Token 重新驗證，同一個身分。Server 端舊 socket 還在等心跳逾時，這段時間兩條都在連線集合裡，不會讓玩家顯示離線。腳本與紀錄在修復 PR 的本機證據資料夾。

## C. Server 重啟

`role4c-server-restart.mjs`：遊戲進行中殺掉 Server 再啟動（間隔 1.5 秒）。

| 項目             | 結果                                        |
| ---------------- | ------------------------------------------- |
| 主持人畫面       | Server 起來後 0.5 秒顯示「房間已失效」      |
| 玩家手機         | Server 起來後 1.6 秒顯示「房間已失效」      |
| 重啟後 Event Log | 該房間 13 筆事件還查得到（SQLite 在檔案裡） |
| Game ID          | `58796882-4864-4966-9829-9065f71c1c69`      |

遊戲狀態只在記憶體，重啟後無法續玩，PRD 允許這一點，列入已知限制。
