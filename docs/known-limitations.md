# 已知限制與後續改善建議

這些是 MVP 刻意不做、或探索式 QA 找到但沒修的事。QA 編號對應 [qa/bugs.md](qa/bugs.md)。**沒有 P0、P1。** QA-01、QA-09 已由修復 PR 修好，不再列在下面（見 [decisions.md](decisions.md#修正-qa-01qa-09)）。

## 設計上的限制

| 限制                                   | 說明                                                                                                                                                                                                           | 影響                                                                                                           |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Server 重啟後遊戲遺失**              | 房間、玩家、遊戲狀態只在記憶體。QA 實測：遊戲進行中重啟 Server，主持人與手機都在 0.5 到 1.6 秒內顯示「房間已失效」。Event Log 在 SQLite 裡，重啟後仍查得到。PRD 允許這一點。                                   | 更新或當機會中斷正在玩的人，部署時請避開遊戲時段。                                                             |
| **只能單一程序**                       | 狀態在記憶體，沒有共用儲存，不能放在多台機器後面。                                                                                                                                                             | 規模以一台機器、同時多個房間為限。沒有做超過 15 人與多房間壓力測試。                                           |
| **App 切換器縮圖無法完全遮蔽**         | 網頁拿不到作業系統的縮圖機制。目前的做法：頁面進背景、失去焦點、關閉時自動隱藏題目並蓋上遮罩，連線中斷時不畫卡片，隱藏時詞語不在 DOM 裡。但作業系統可能在網頁來得及反應前就截圖，iOS 與 Android 的行為也不同。 | 真機結果還沒測，見 [manual-test-checklist.md](manual-test-checklist.md) A5。若要更強的保護，只能做成原生 App。 |
| **玩家離線不會被移除**                 | 總覽假設 1：不做主持人踢人。Lobby 中離場沒按離開的玩家仍算在名單，會被算進下一場；遊戲中離線的玩家也一直留著。                                                                                                 | 主持人要口頭處理。建議之後加「主持人移除玩家」。                                                               |
| **Token 只存在瀏覽器**                 | 主持人 Token 只在開房間那個瀏覽器的 localStorage。玩家 Token 一樣。換瀏覽器或清除網站資料就回不到座位（QA-02、QA-06）。                                                                                        | 主持人要用同一個瀏覽器開到結束。                                                                               |
| **Token 12 小時、房間閒置 2 小時清除** | 總覽假設 4。                                                                                                                                                                                                   | 房間放著超過 2 小時沒人操作會消失。                                                                            |
| **Event Log 保留 30 天**               | 超過的自動刪除，沒有備份機制。                                                                                                                                                                                 | 要長期保存請自己備份 `events.db`。                                                                             |
| **深色模式只跟系統設定**               | 沒有手動切換。                                                                                                                                                                                                 |                                                                                                                |

## 視覺與部署

| 限制                               | 說明                                                                                                                                                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **綠色 `#1d8a4a` 只符合大字的 AA** | 與淺色底的對比約 4.4:1，達不到一般文字要求的 4.5:1，但超過大字（3:1）。它只用在揭曉標題、副標與卡片框線，都是大字。`tests/integration/contrast.test.ts` 把這幾組用 3:1 檢查。若要拿來當小字，要先調深。 |
| **`og:image` 是相對路徑**          | `index.html` 的 `og:image` 寫 `/og.png`。部分平台分享連結時要求絕對網址才會顯示預覽圖。後續可由 Server 回 `index.html` 時，用 `PUBLIC_BASE_URL` 換成絕對網址。不影響遊戲。                              |
| **沒有正式環境的監控與告警**       | 本票明確不做。只有 `/healthz` 與 Event Log。                                                                                                                                                            |

## 沒有驗證的事

- **真機與投影還沒測。** iOS Safari、Android Chrome、鎖屏、App 切換、換網路、會議室投影、6 到 10 人完整一場，全部在 [manual-test-checklist.md](manual-test-checklist.md)，結果欄是「待執行」。AI Agent 的 QA 只用桌面 Chromium 模擬 iPhone 13 的視窗與使用者代理。
- **Docker 映像檔只在本機建置並檢查過 `/healthz`**，沒有跑過 Nginx 或 Caddy 反向代理，見 [test-report.md](test-report.md)。
- **PRD 第 12 章 Definition of Done**：PRD 不在 repo 內。本票用各張票與總覽的驗收條件對照（見 PR 描述），第 12 章要由 Tony 自己逐項確認。

## 後續改善建議（依價值排序，都不在 MVP 範圍）

1. 用真機驗證換網路、鎖屏後的重連時間（QA-01 已縮短到最久 20 秒，見 [manual-test-checklist.md](manual-test-checklist.md) A7）。
2. 主持人移除玩家，與主持人 Token 的復原方式（QA-02、QA-06）。
3. 首頁的房間代碼輸入欄、題目卡的操作提示（QA-03、QA-04）。
4. 用 `PUBLIC_BASE_URL` 產生絕對網址的 `og:image`。
5. 把房間狀態存到共用儲存，讓 Server 重啟不中斷遊戲，也才能多程序。
